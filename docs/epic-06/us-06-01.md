# US-06-01 — Contrat d'inférence et registre extensible

**Branche :** `epic/06-inference-web-app`

## 1. Objectif

Définir une interface commune permettant à l'application web
d'utiliser différents modèles indépendamment de leur architecture.

## 2. Implémentation

### Contrat

`src/inference/inference_contract.py`

Entrée :
- category : bottle, hazelnut ou transistor
- method : cae ou patchcore
- version : identifiant de version
- image : Tensor RGB [3, H, W], flottant dans [0, 1]

Sortie :
- category, method, version
- score : score brut
- threshold : seuil de décision
- anomaly_map : Tensor [H, W], sur CPU
- decision : normal ou suspect
- latency_ms : latence CPU mesurée
- simulated : indicateur de simulation

### Registre

`src/inference/model_registry.py`

Configuration :
`configs/model_registry.json`

Chaque modèle est identifié par le triplet :
(category, method, version).

Le registre contient six entrées de démonstration.
Toutes utilisent le backend "fake" sans checkpoint réel.

### Modèle factice

FakeModel utilise une référence constante de 0.5

Carte : moyenne des écarts absolus entre les canaux RGB
et cette référence.

Score : moyenne de la carte.

Seuil fictif : 0.2.

Ce score et ce seuil ne constituent pas une détection
scientifiquement validée. Ils servent uniquement à
vérifier le fonctionnement du contrat.

Le calcul est déterministe pour une même image.
La latence mesurée peut varier entre exécutions.

## 3. Tests et reproductibilité

Environnement : Python avec PyTorch et pytest.

Aucun GPU, dataset, checkpoint ou notebook Kaggle nécessaire.

Depuis la racine du dépôt :

```powershell
python -m pytest -q tests/inference/test_inference_contract.py
python -m pytest -q tests/inference
```

Les tests couvrent :
- Chargement et recherche dans le registre
- Modèles dupliqués et configurations invalides
- Chargement du modèle factice sur CPU
- Contrat d'entrée/sortie et sérialisation
- Décisions normales et suspectes
- Rejet des images invalides
- Refus des backends non intégrés

## 4. Compatibilité et limites

Les moteurs existants CAE et PatchCore restent inchangés.

Ils fournissent déjà un score brut et une carte d'anomalie.
Leur raccordement au contrat est prévu dans US-06-03.

La calibration des seuils relève de l'EPIC-05.
Les métriques de cette simulation ne doivent pas être
utilisées dans le benchmarking scientifique.

Aucune expérience Kaggle ni nouvel EXP-XXX n'est créée :
il s'agit d'une validation technique locale.
