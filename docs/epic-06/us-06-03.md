# US-06-03 — Intégration des six modèles réels

**Branche de développement :** `epic/06-inference-web-app`

## 1. Objectif

Intégrer les six modèles entraînés pendant les EPIC-03 et EPIC-04
dans le pipeline d'inférence commun et dans l'application Streamlit.

Combinaisons :
- CAE : Bottle, Hazelnut, Transistor.
- PatchCore : Bottle, Hazelnut, Transistor.

Les modèles sont restaurés depuis des checkpoints existants.
Aucun réentraînement ni recalcul de Memory Bank n'est réalisé.

## 2. Architecture

| Composant | Responsabilité |
|---|---|
| `configs/real_model_registry.json` | Référencer les six modèles réels |
| `src/inference/model_registry.py` | Valider et rechercher les modèles |
| `src/inference/model_loader.py` | Restauration CPU, SHA-256 et cache |
| `src/inference/cae_inference.py` | Prédiction CAE |
| `src/inference/patchcore_inference.py` | Prédiction PatchCore |
| `src/inference/inference_contract.py` | Contrat commun et orchestration |
| `src/data/transforms.py` | Prétraitement déjà existant, inchangé |
| `app/streamlit_app.py` | Sélection et inspection |
| `app/result_view.py` | Affichage des résultats |

Le registre simulé `configs/model_registry.json` est conservé.
Le mode simulé reste disponible dans Streamlit.

Pipeline :

1. Réception d'une image RGB.
2. Validation du tenseur `[3, H, W]` dans `[0, 1]`.
3. Recherche du modèle dans le registre.
4. Restauration CPU ou récupération depuis le cache.
5. Prétraitement adapté au modèle.
6. Appel à `engine.predict()`.
7. Production d'un `InferenceResult` commun.
8. Affichage du score, de la latence et de la carte.

## 4. Restauration et intégrité

### 4.1. CAE

Les poids sont restaurés avec `CAEInference.from_checkpoint()`.

La configuration d'architecture utilisée est :
`experiments/configs/cae_baseline.json`.

L'intégrité SHA-256 est vérifiée avant la restauration.

### 4.2. PatchCore

La restauration utilise `PatchCoreInference.from_checkpoint()`.

Deux schémas de checkpoints sont pris en charge :

- Format original : `model_state_dict` et métadonnées à la racine.
- Format Hazelnut EXP-002 : `state_dict` et `config`.

Les poids sont chargés avec `weights_only=True`.
La restauration du state_dict est stricte (`strict=True`).

Le backbone est reconstruit sans télécharger de nouveaux poids
(`pre_trained=False`).

Les Memory Banks sauvegardées sont restaurées, jamais recalculées.

Dimensions vérifiées :

| Modèle | Memory Bank |
|---|---|
| PatchCore Bottle | `(1710, 1536)` |
| PatchCore Hazelnut | `(3205, 1536)` |
| PatchCore Transistor | `(1740, 1536)` |

## 5. Chargement CPU et cache

Le module `model_loader.py` utilise `lru_cache(maxsize=1)`.

Comportement :

- Premier appel : vérification d'intégrité et restauration du checkpoint.
- Deuxième appel identique : récupération du moteur depuis le cache.
- Changement de modèle : remplacement de l'entrée du cache.
- `clear_model_cache()` : suppression de la référence mise en cache.

Le cache conserve au maximum une entrée, sans garantir
la libération immédiate de toute la RAM si d'autres références
au modèle existent encore.

Tous les moteurs sont restaurés en mode évaluation sur CPU.

Le chargement à la demande évite de restaurer simultanément
les six modèles.

## 6. Prétraitement

Le composant existant `MVTecTransform` est réutilisé sans
modifier `src/data/transforms.py`.

Comme ce composant attend une image et un masque,
l'inférence utilise un masque vide temporaire.

Profils :

| Paramètre | CAE | PatchCore |
|---|---|---|
| Taille | 256 × 256 | 256 × 256 |
| Image | RGB, float32 | RGB, float32 |
| Normalisation ImageNet | Non | Oui |
| Entrée du modèle | `[3,256,256]` | `[3,256,256]` |

La conversion intermédiaire en image PIL suit le chemin
de prétraitement existant du projet.

## 7. Contrat d'inférence

Entrée : `InferenceRequest`.

Sortie : `InferenceResult`, contenant notamment :

- category, method, version ;
- score brut ;
- threshold ;
- anomaly_map ;
- decision ;
- latency_ms ;
- simulated.

Pour les modèles réels actuellement intégrés :

- `simulated = False`
- `threshold = None`
- `decision = "non_calibree"`

Aucune décision NORMAL/SUSPECT n'est produite sans seuil calibré.

La calibration scientifique des seuils relève de l'EPIC-05.

Les scores CAE et PatchCore ne sont pas directement
comparables : ils proviennent de méthodes différentes.

La normalisation min-max utilisée par Streamlit concerne
uniquement la représentation visuelle des cartes.

## 9. Résultats de validation locale


### 9.1. Script de validation reproductible

Depuis la racine du dépôt, avec l'environnement virtuel activé
et les six checkpoints présents dans `artifacts/`, exécuter
le script PowerShell suivant :

```powershell
@'
import gc
import math

import torch

from src.inference.model_registry import load_registry
from src.inference.model_loader import clear_model_cache
from src.inference.inference_contract import (
    InferenceRequest,
    run_inference,
)

registry = load_registry("configs/real_model_registry.json")

models = [
    ("bottle", "cae", "exp-002"),
    ("hazelnut", "cae", "exp-001"),
    ("transistor", "cae", "exp-001"),
    ("bottle", "patchcore", "exp-002"),
    ("hazelnut", "patchcore", "exp-002"),
    ("transistor", "patchcore", "exp-001"),
]

image = torch.full(
    (3, 256, 256),
    0.5,
    dtype=torch.float32,
)

for category, method, version in models:
    request = InferenceRequest(
        category=category,
        method=method,
        version=version,
        image=image,
    )

    result = run_inference(request, registry)

    assert result.simulated is False
    assert result.threshold is None
    assert result.decision == "non_calibree"
    assert math.isfinite(result.score)
    assert result.anomaly_map.shape == (256, 256)
    assert torch.isfinite(result.anomaly_map).all()

    print(
        f"{category.upper()} / {method.upper()} / {version} : OK"
    )
    print(f"Score brut : {result.score:.6f}")
    print(f"Latence : {result.latency_ms:.1f} ms")
    print()

    del result
    clear_model_cache()
    gc.collect()

print("SIX INFERENCES REELLES : OK")
'@ | python -
```

Le script termine avec :

```text
SIX INFERENCES REELLES : OK
```

Les scores peuvent varier légèrement selon les versions
des bibliothèques et les conditions d'exécution.
Les latences dépendent également du matériel et du cache.

Ce test utilise une image synthétique uniforme. Il valide
l'intégration technique et ne mesure pas la performance
scientifique de détection des anomalies.

## 10. Erreurs et limites

Les contrôles couvrent notamment :

- Modèle absent du registre.
- Configuration incomplète ou invalide.
- Checkpoint manquant.
- SHA-256 incorrect.
- Format de checkpoint inconnu.
- Memory Bank invalide.
- Image d'entrée invalide.
- Score ou carte d'anomalie non fini.

Une erreur de chargement est propagée au pipeline et affichée
dans Streamlit sous la forme d'un message d'erreur.

Limites connues :

- Le fonctionnement est validé sur CPU local.
- Les premières inférences peuvent être plus lentes en raison
  de la restauration des checkpoints et des imports.
- Les seuils ne sont pas encore calibrés.
- Les performances de détection ne sont pas évaluées dans cette US.
- L'affichage avancé et l'export de rapports relèvent de l'US-06-04.
- Les checkpoints volumineux ne sont pas versionnés dans Git.

## 11. Conclusion

- Six combinaisons catégorie/méthode intégrées.
- Restauration des artefacts sans réentraînement.
- Chargement CPU à la demande avec cache.
- Gestion et tests des erreurs.
