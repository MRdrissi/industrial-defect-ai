# US-06-02 — Interface Streamlit et importation d'images

**Branche :** `epic/06-inference-web-app`

## 1. Objectif

Développer une application web Streamlit permettant à l'utilisateur de :

- Sélectionner une catégorie industrielle : Bottle, Hazelnut ou Transistor.
- Choisir une méthode : CAE ou PatchCore.
- Sélectionner une version du modèle.
- Importer une image PNG ou JPEG.
- Exécuter une inférence simulée.
- Visualiser la décision, le score, le seuil, la latence et la carte d'anomalie.

L'application réutilise le contrat d'inférence et le registre développés dans l'US-06-01.

Cette US ne réalise pas encore d'inférence avec les modèles Deep Learning réels.

## 2. Architecture et implémentation

### 2.1. Organisation modulaire

L'application est organisée en trois composants Python :

| Fichier | Responsabilité |
|---|---|
| `app/streamlit_app.py` | Interface principale, sélection et orchestration |
| `app/image_utils.py` | Validation et conversion des images |
| `app/result_view.py` | Affichage des résultats d'inférence |

Le répertoire `app/` possède également un fichier `__init__.py` et un fichier `requirements.txt`.

Cette organisation sépare l'interface, le traitement des images et la présentation des résultats sans ajouter de complexité inutile.

### 2.2. Sélection des modèles

Les modèles disponibles sont lus depuis :

`configs/model_registry.json`

Les sélecteurs Streamlit sont générés dynamiquement à partir des configurations enregistrées.

Chaque modèle est identifié par :

`(category, method, version)`

Le registre contient actuellement six configurations de démonstration : trois catégories et deux méthodes.

Toutes utilisent le backend `fake` et la version `demo-v1`.

### 2.3. Importation et prétraitement

Le module `app/image_utils.py` assure :

- La vérification des fichiers PNG et JPEG.
- Le rejet des fichiers vides ou invalides.
- La limitation à 10 Mo par image.
- La limitation à 16 millions de pixels.
- La conversion en image RGB.
- La conversion en tenseur PyTorch `[3, H, W]` avec des valeurs dans `[0, 1]`.

### 2.4. Inférence simulée

L'application réutilise les composants développés dans l'US-06-01 :

- `InferenceRequest`
- `run_inference()`
- `InferenceResult`

Le modèle factice calcule une carte d'écarts absolus par rapport à une référence constante de `0.5`.

Le score correspond à la moyenne de cette carte.

Le seuil de démonstration est fixé à `0.2`.

La décision est calculée comme suit :

- `score < 0.2` : NORMAL
- `score >= 0.2` : SUSPECT

Ces résultats sont artificiels et ne constituent pas une véritable détection de défaut industriel.

## 3. Environnement et exécution

### 3.1. Prérequis

- Python et environnement virtuel du projet.
- PyTorch, NumPy, Pillow et pytest.
- Streamlit, déclaré dans `app/requirements.txt`.

### 3.2. Installation

Depuis la racine du dépôt :

```powershell
python -m pip install -r app/requirements.txt
```

### 3.3. Démarrage de l'application

```powershell
python -m streamlit run app/streamlit_app.py
```

L'application est accessible localement, par défaut, à l'adresse :

`http://localhost:8501`

## 4. Validation manuelle reproductible

### 4.1. Objectif

Valider le parcours complet de l'application sans utiliser le dataset MVTec AD ni les checkpoints réels.

Deux images synthétiques sont utilisées afin d'obtenir des décisions prévisibles avec le modèle factice.

### 4.2. Génération des images

Depuis la racine du dépôt, exécuter dans PowerShell :

```powershell
@'
from PIL import Image
from pathlib import Path

folder = Path("data/ui-test")
folder.mkdir(parents=True, exist_ok=True)

Image.new("RGB", (256, 256), (128, 128, 128)).save(folder / "normal.png")
Image.new("RGB", (256, 256), (0, 0, 0)).save(folder / "suspect.png")

print("Images créées dans data/ui-test/")
'@ | python -
```

Les deux fichiers générés sont :

| Image | Contenu | Dimensions |
|---|---|---|
| `data/ui-test/normal.png` | Gris uniforme RGB (128, 128, 128) | 256 × 256 |
| `data/ui-test/suspect.png` | Noir uniforme RGB (0, 0, 0) | 256 × 256 |

Le dossier `data/` est ignoré par Git. Ces images ne sont donc pas publiées dans le dépôt.

### 4.3. Scénario 1 — Image normale

Dans Streamlit :

1. Sélectionner `bottle`.
2. Sélectionner `CAE`.
3. Conserver `demo-v1`.
4. Importer `normal.png`.
5. Vérifier l'aperçu.
6. Cliquer sur **Analyser l'image**.

Résultats attendus :

| Élément | Valeur attendue |
|---|---|
| Score brut | Environ 0.00196 |
| Seuil | 0.2 |
| Décision | NORMAL |
| Carte d'anomalie | 256 × 256 |
| Latence | Valeur mesurée, positive ou nulle |
| Simulation | `true` |

La décision NORMAL est attendue, car les pixels de l'image sont très proches de la référence `0.5`.

### 4.4. Scénario 2 — Image suspecte

Répéter la même procédure en important `suspect.png`.

Résultats attendus :

| Élément | Valeur attendue |
|---|---|
| Score brut | 0.5 |
| Seuil | 0.2 |
| Décision | SUSPECT |
| Carte d'anomalie | 256 × 256 |
| Latence | Valeur mesurée, positive ou nulle |
| Simulation | `true` |

La décision SUSPECT est attendue, car l'écart entre les pixels noirs (`0.0`) et la référence (`0.5`) est de `0.5`.

### 4.5. Gestion des erreurs

Vérifications complémentaires à effectuer :

- Cliquer sur Analyser sans importer d'image : un avertissement doit apparaître.
- Importer un fichier invalide avec une extension PNG : l'application doit afficher une erreur lisible.
- Changer de catégorie et de méthode : les sélecteurs doivent rester fonctionnels.
- Vérifier que les informations techniques correspondent au modèle sélectionné.

### 4.6. Bilan de validation manuelle

Les deux images de test ont été générées à l'aide du script Python documenté ci-dessus.

Les résultats constatés dans le navigateur restent à consigner :

| Scénario | Résultat attendu | Statut |

## 6. Limites

L'application constitue une première interface fonctionnelle, mais avec plusieurs limites explicites :

- Aucune inférence réelle CAE ou PatchCore.
- Aucun checkpoint chargé.
- Aucun prétraitement spécialisé selon le modèle.
- Aucun seuil calibré scientifiquement.
- Aucun résultat utilisable pour le benchmarking industriel.

Le modèle factice classe les images selon leur écart à une valeur de référence, et non selon la présence réelle de défauts.

L'intégration des modèles réels est prévue dans l'US-06-03.

La calibration scientifique appartient à l'EPIC-05.

Cette US ne nécessite ni Kaggle, ni GPU, ni nouvelle expérience `EXP-XXX`.
