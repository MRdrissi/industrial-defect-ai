## ST-03-04-01 — Apprentissage et sélection

Le [manifeste figé](../data/us-02-03/hazelnut_manifest.csv) sépare 313 normales pour l’apprentissage et 78 pour la validation. Les deux splits proviennent de `hazelnut/train/good/`. Le test officiel est réservé à l’évaluation ultérieure. Empreinte SHA-256 du manifeste : `8f0e0d5b5bb767cd2d2e6f8a0ab10f65a959a97a38bb14bc5d9aae1d30c81fb6`.

Le [profil CAE](../epic-02/us-02-04.md) fournit des tenseurs RGB 256 × 256 dans `[0,1]`, utilisés comme entrée et cible de reconstruction. La [baseline V1](us-03-01.md) compte 855 619 paramètres, avec 32/64/128 canaux d’encodeur, un bottleneck de 128 × 16 × 16 et une sortie Sigmoid.

| Paramètre | Valeur exécutée |
|---|---|
| Optimisation | Adam, LR 0,001 constant, MSE, batch 16 |
| Reproductibilité | Seed 42, 2 workers, cuDNN déterministe, benchmark désactivé |
| Arrêt | Maximum 150 époques, patience 20, amélioration significative de `0.000001` |
| Environnement | Tesla T4, Python 3.13.16, PyTorch 2.11.0+cu130 |

Les pertes sont pondérées par le nombre réel d’images de chaque lot. La patience utilise le seuil d’amélioration significative, tandis que la sauvegarde retient toute baisse stricte de la MSE de validation. Après l’essai d’une époque, le notebook réinitialise les générateurs, les loaders, le modèle et l’optimiseur pour le run officiel. ## ST-03-04-02 — Restauration et reproduction

Le checkpoint `cae/hazelnut/hazelnut-baseline-001/best_model.pt` se trouve dans les Outputs du notebook Training. Il contient le `model_state_dict`, la configuration du modèle, l’époque, la MSE minimale, le SHA Git et le SHA du manifeste. Son SHA-256 mesuré par le notebook de restauration est `34ab16490dc5e75003971a54e53bbda61b2f6be9428f63ace322b06c64d7e811`. [Training sur Kaggle](https://www.kaggle.com/code/marwanedrissi/industrialdefect-ai-cae-hazelnut-training) · [Restoration sur Kaggle](https://www.kaggle.com/code/marwanedrissi/industrialdefect-ai-cae-hazelnut-restore-check)

1. **Provenance.** Le commit `742b8346e664b4efc50410b3707bdb2db6908c1f` identifie le modèle, le pipeline et la configuration clonés pendant l’expérience. Ce commit contenait le notebook de préparation. La boucle complète a été exécutée sur Kaggle puis archivée dans Git avec ses sorties. Les deux notebooks exécutés sont archivés au commit [`96649ad`](https://github.com/MRdrissi/industrial-defect-ai/commit/96649ad7ad571537a2afee5690dd3b00a08ab479). Les liens Kaggle disponibles désignent les pages des notebooks. Les identifiants immuables des versions exécutées restent à renseigner.
2. **Reproduire le Training.** Attacher `ipythonx/mvtec-ad`, activer le GPU, importer le notebook complet archivé et préparer un clone du dépôt au SHA `742b834` sous `/kaggle/working/industrial-defect-ai` avant la première cellule. Cela permet de conserver la cellule historique qui référence la branche feature. Vérifier le SHA imprimé. Utiliser une session neuve ou un répertoire de run vide. Conserver les Outputs d’une version Kaggle après l’exécution.
3. **Reproduire uniquement l’inférence.** Dans une session CPU neuve, attacher MVTec AD et les Outputs Training contenant le checkpoint, `run_info.json` et `history.csv`. Prévoir l’accès au dépôt pour le clonage. Le notebook de restauration récupère le commit indiqué dans le checkpoint, reconstruit le modèle, charge les poids sur CPU avec `weights_only=True` et `strict=True`, puis évalue les 78 normales en mode inférence, sans réentraînement.

La MSE restaurée vaut **0,00020595182242811235**, soit un écart absolu de **1,88 × 10⁻¹¹** et un écart relatif de **0,00000912 %**. Le rapport confirme que l’écart absolu est inférieur à la tolérance de **2,06 × 10⁻⁷**. Cette expérience valide la reconstruction des normales et la restauration des poids. La performance de détection et de localisation des anomalies reste à mesurer sur le protocole d’évaluation prévu.
