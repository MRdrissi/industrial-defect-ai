# US-05-03 — Benchmark Test, phase 1

**Périmètre livré : orchestrateur local et tests synthétiques. Aucune exécution réelle Test.**

Le point d'entrée `python -m src.evaluation.run_benchmark` prépare une instance ou les six
configurations du catalogue figé. Il réutilise les seuils de US-05-02, la restauration existante
(dont PatchCore Hazelnut EXP-002 corrigée), les métriques, les masques et les exports de US-05-01.
Les macro-moyennes, la comparaison scientifique finale et l'exécution Kaggle sont hors phase 1.

## Contrat scientifique

- Le catalogue, le protocole 1.1.0 et le registre sont vérifiés contre des empreintes externes
  épinglées dans le module. Les six associations famille/catégorie/checkpoint/manifeste/protocole
  doivent correspondre avant toute restauration. L'ancre du registre reste
  `41dd9d26e68840ca5d104062605d967e72a2d3907937e8ed6745743034c96b6a`.
- Seules les lignes du **split logique `test`** du manifeste vérifié sont transmises au chargeur.
  Les chemins sont canoniques, uniques entre splits et confinés à la racine du dataset. Images
  et masques attendus doivent exister. Les fichiers hors de cette sélection ne sont pas évalués.
  La liste du chargeur et chaque échantillon sont comparés à la sélection complète, sans omission,
  doublon ni ajout. Les étiquettes Test servent uniquement à l'évaluation.
- Le SHA-256 du checkpoint est contrôlé avant restauration. Aucun entraînement, reconstruction
  de banque mémoire, appel au workflow de calibration ou ajustement de seuil n'est effectué.
- Scores bruts identiques aux API existantes : CAE = maximum de l'erreur quadratique moyenne
  par canal, lissée avec sigma 4 et noyau 33 ; PatchCore = `pred_score` natif.
  Aucune normalisation sur Test. Classification par `score > threshold`, AUROC sur scores continus.
- Le chargeur commun convertit explicitement les masques 0/255 en binaire. Une normale sans masque
  reçoit un masque nul ; une anomalie sans masque, avec masque vide ou de dimensions incohérentes
  est refusée. Résolution 256 × 256, nearest pour les masques, bilinéaire pour les cartes.
  Pixel-AUROC regroupe les pixels de toutes les images de l'instance.

## Latence et adaptateur d'inférence

Les méthodes publiques `predict()` existantes effectuent aussi des copies vers le CPU.
L'adaptateur local `_predict_on_device` utilise donc le modèle restauré et, pour le CAE,
son lissage existant. Il conserve score et carte sur le device jusqu'à la fin du chronométrage.
Un test compare exactement ses scores/cartes aux deux API existantes avec des modèles synthétiques.

Le périmètre chronométré comprend le forward et le calcul brut du score/de la carte.
Lecture disque, prétraitement, transfert d'entrée, copies de sortie vers le CPU, conversion scalaire
et alignement spatial d'évaluation sont exclus. Batch 1 ; trois échauffements sur la première
image de l'ordre déterministe du manifeste, indépendamment de son label ; synchronisation CUDA
après chaque échauffement et avant/après chaque mesure. Les échauffements ne sont pas exportés.

## Utilisation prévue lors d'une phase ultérieure autorisée

Depuis un checkout committé, avec les dépendances scientifiques et les fichiers déjà disponibles :

```bash
python -m src.evaluation.run_benchmark \
  --instance cae-transistor \
  --dataset-root /kaggle/input/datasets/ipythonx/mvtec-ad \
  --checkpoint /kaggle/input/datasets/marwanedrissi/industrialdefect-us0502-missing-checkpoints/cae/transistor/best_model.pt \
  --output /kaggle/working/benchmark-us0503/cae-transistor \
  --device cuda:0 \
  --preflight
```

`--preflight` vérifie les empreintes, les associations et l'inventaire des fichiers sans restaurer
le modèle, décoder les images ou produire d'export scientifique. Il ne qualifie pas le runtime,
le GPU ni le contenu des images/masques : ces vérifications interviennent à l'exécution.
Le manifeste Test temporaire est supprimé à la fin du précontrôle.
Retirer `--preflight` uniquement lors de la phase d'exécution réelle autorisée.
Les chemins ci-dessus restent à confirmer dans la session d'exécution.

Pour les six configurations, fournir un JSON associant exactement les six identifiants du catalogue
à leurs chemins de checkpoints, puis utiliser :

```bash
python -m src.evaluation.run_benchmark \
  --instance all --checkpoints-json /kaggle/working/checkpoints-us0503.json \
  --dataset-root /kaggle/input/datasets/ipythonx/mvtec-ad \
  --output /kaggle/working/benchmark-us0503-six --device cuda:0 --preflight
```

Identifiants : `cae-bottle`, `cae-hazelnut`, `cae-transistor`, `patchcore-bottle`,
`patchcore-hazelnut`, `patchcore-transistor`. Les six précontrôles terminent avant toute inférence.
Le module fournit aussi les fonctions Python `run_instance(...)` et `run_all(...)`.

## Exports et reprise

Chaque instance produit `predictions.csv`, `metrics.json`, `manifest.json` et `artifacts/*.npz`,
avec les empreintes des artefacts. Les métadonnées incluent le seuil exact et son hex, les ancres
du registre/calibration, les empreintes du checkpoint/manifeste/protocole/catalogue/configuration,
le commit exécuté, le matériel, les versions, les prétraitements et le périmètre de latence.
Le résultat retourné fournit aussi le SHA-256 du manifeste d'export à conserver hors du dossier.

Un dossier de sortie existant est refusé. Chaque export est publié par l'exporteur existant ;
le lancement des six n'est pas une transaction globale. En cas d'échec tardif, conserver les exports
déjà réussis et reprendre uniquement les instances restantes avec des destinations neuves.
Un checkout contenant des changements non committés dans `src/` ou `experiments/configs/`
est refusé avant restauration. Les modifications locales de notebooks n'entrent pas dans ce contrôle.

de faux checkpoints et des modèles factices CPU. Ils couvrent la sélection/couverture Test,
les empreintes et associations incorrectes, les seuils réels chargés sans recalibration,
les masques, les `EvaluationRecord`, les exports, le chronométrage et le routage une/six instances.

réussis** (16,43 s) sur l'orchestrateur et ses dépendances directes, sans échec.
