# US-04-02 — Construire la Memory Bank PatchCore — Bottle

## Objectif

Construire une Memory Bank PatchCore à partir des 167 images normales Bottle du split Train de MVTec AD.

Cette US prolonge l'US-04-01, qui avait validé l'intégration de PatchCore sur Kaggle avec seulement 8 images normales.

L'expérience `patchcore-bottle/EXP-002` utilise le backbone Wide ResNet-50-2 pré-entraîné et gelé, puis sélectionne un sous-ensemble représentatif des caractéristiques avec KCenterGreedy.

## Protocole expérimental

### Données

- Dataset : MVTec AD, catégorie Bottle.
- Source Kaggle : `ipythonx/mvtec-ad` v2.
- Train : 167 images normales.
- Validation : 42 images normales.
- Test officiel : non utilisé.

Les splits proviennent du manifeste figé de l'EPIC-02 :

`docs/data/us-02-03/bottle_manifest.csv`

Le pipeline US-02-04 redimensionne les images à 256 × 256 et applique la normalisation ImageNet.

### Configuration PatchCore

| Paramètre | Valeur |
|---|---|
| Backbone | wide_resnet50_2 |
| Poids pré-entraînés | Oui |
| Backbone gelé | Oui |
| Couches | layer2, layer3 |
| Dimensions des embeddings | 1536 |
| Batch size | 2 |
| Seed | 42 |
| Coreset | KCenterGreedy |
| Sampling ratio | 0.01 |
| Plus proche voisin | 1 |

Aucune optimisation par epochs n'est effectuée. Les poids du backbone restent gelés.

## Construction de la Memory Bank

Le notebook GPU exécute les opérations suivantes :

1. Charger les 167 images normales du split Train.
2. Extraire les caractéristiques de chaque image.
3. Construire une matrice de 171 008 vecteurs de dimension 1 536.
4. Appliquer KCenterGreedy avec un ratio de 1 %.
5. Enregistrer les 1 710 vecteurs sélectionnés dans la Memory Bank.
6. Passer PatchCore en mode inférence.

### Résultats observés

| Mesure | Résultat |
|---|---:|
| Images Train traitées | 167 |
| Embeddings extraits | 171 008 |
| Dimensions des embeddings | 1 536 |
| Taille finale de la Memory Bank | 1 710 |
| Sampling ratio | 1 % |
| Dimensions de la carte d'anomalie | 256 × 256 |
| Score brut Validation | 29.36626434326172 |

Les embeddings et les vecteurs mémorisés possèdent des valeurs finies.

L'image utilisée pour le scoring est :

`bottle/train/good/002.png`

Elle appartient au split logique Validation et ne figure pas parmi les 167 images de construction de la Memory Bank.

Le score est brut et non calibré. Il ne constitue pas une probabilité d'anomalie.

[Rapport GPU](../data/us-04-02/memory_bank_report.json) · [Visualisation](../data/us-04-02/anomaly_visualization.png)

## Checkpoint et restauration

Le modèle est sauvegardé dans les Outputs Kaggle :

`patchcore/bottle/EXP-002/patchcore_model.pt`

SHA-256 :

`dcf0f8df3dc9b4be9ee1bcb897d3ec6f24a3191240dcfd4e68afd598acd77cde`

Le checkpoint contient les poids du backbone, la Memory Bank et les paramètres nécessaires à la reconstruction du modèle.

Une première restauration dans la même session GPU a reproduit le score et la carte d'anomalie de référence.

### Restauration CPU indépendante

Le notebook `15-patchcore-bottle-restore-check.ipynb` est destiné à une nouvelle session Kaggle CPU.

Il vérifie :

- L'intégrité SHA-256 du checkpoint.
- La correspondance du commit et du tag Git.
- La correspondance des configurations et du manifeste.
- Le rechargement strict du `state_dict`.
- La restauration des 1 710 vecteurs sans recalcul du Coreset.
- La cohérence numérique entre les prédictions CPU et GPU.

Les résultats numériques et le statut définitif de la restauration indépendante sont enregistrés dans :

[Rapport CPU](../data/us-04-02/restore_report.json)

Les tolérances prévues sont :

| Mesure | Tolérance |
|---|---:|
| Écart absolu du score | 0.001 |
| Écart absolu maximal de la carte | 0.001 |
| Écart maximal relatif à l'étendue de la carte | 0.0001 |

## Reproductibilité

https://www.kaggle.com/code/mouadfekkak/14-patchcore-bottle-memory-bank?scriptVersionId=369295449

1. Ouvrir le notebook 15 dans une nouvelle session Kaggle.
2. Sélectionner Accelerator = None.
3. Activer Internet.
4. Attacher MVTec AD v2.
5. Attacher les Outputs de l'expérience GPU EXP-002.
6. Exécuter toutes les cellules.
7. Vérifier le statut final dans `restore_report.json`.

Aucun réentraînement ni recalcul du Coreset n'est nécessaire.

## Limites

Cette US valide la construction, la sauvegarde et la restauration de la Memory Bank Bottle.

Elle ne réalise pas encore de calibration du seuil d'anomalie.

Les métriques Image AUROC, Pixel AUROC, Precision, Recall et F1-score restent à calculer lors de l'évaluation sur le split Test officiel.
