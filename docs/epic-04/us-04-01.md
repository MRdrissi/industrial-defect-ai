## Protocole et environnement

Le [manifeste Bottle](../data/us-02-03/bottle_manifest.csv) fournit 167 normales de train et 42 de validation. Le notebook sélectionne huit indices avec `torch.randperm` et la seed 42. Les huit chemins figurent dans le rapport GPU. L’image `bottle/train/good/002.png` appartient au split logique `val` et reste extérieure à la banque. Le test officiel est réservé à l’évaluation ultérieure.

Le pipeline US-02-04 lit le manifeste au commit [`0a6f5fa`](https://github.com/MRdrissi/industrial-defect-ai/commit/0a6f5fac7b47fcaa797d65774e7442ed0201de1f). Ce SHA identifie le code de données utilisé. Les versions Kaggle ci-dessous identifient le code expérimental exécuté. Le profil `patchcore` redimensionne les images RGB à 256 × 256 et applique une fois la normalisation ImageNet.

## Reproduire le smoke test

1. Ouvrir le [notebook GPU v3](https://www.kaggle.com/code/marwanedrissi/industrialdefect-ai-patchcore-bottle-smoke?scriptVersionId=368924991) ou importer la copie Git dans une session Kaggle avec GPU, Internet et `ipythonx/mvtec-ad` v2. Sur une image compatible avec le couple Torch/Torchvision du tableau, installer au besoin `anomalib==2.7.0 timm==1.0.30 lightning==2.6.6` avec pip, puis exécuter les cellules dans l’ordre. Le [plan pip original](../data/us-04-01/patchcore_install_plan.json) décrit l’état de la session enregistrée.
2. Charger `wide_resnet50_2` pré-entraîné via Anomalib, geler explicitement l’extracteur, puis extraire `layer2` et `layer3`. En mode collecte, l’extracteur reste en mode évaluation. Anomalib 2.7.0 renvoie directement une matrice 2D de patches. Les quatre lots de deux images alimentent `KCenterGreedy`, initialisé avec la seed 42.
3. Affecter le coreset à `memory_bank` et passer le modèle en évaluation avec `num_neighbors=1`. Conserver les Outputs sous `/kaggle/working/patchcore/bottle/smoke-001/`. Le checkpoint `patchcore_model.pt` contient le backbone, la banque, les couches et le nombre de voisins. SHA-256 : `37e3d731aca54d2f0272b79082d21eeafebc96faeda91d19a72a84353451a9fa`.

## Restaurer l’inférence

Dans une session Kaggle CPU neuve, attacher le dataset et les **Outputs de la v3 GPU**. Le [notebook CPU](../../notebooks/13-patchcore-restore-check.ipynb) vérifie les empreintes du checkpoint et du manifeste, construit le modèle avec `pre_trained=False`, puis charge le `state_dict` avec `strict=True`. La banque sauvegardée est ainsi restaurée directement. La comparaison porte sur la même image et la prédiction GPU archivée. [Session CPU v1](https://www.kaggle.com/code/marwanedrissi/industrialdefect-ai-patchcore-bottle-restore-check?scriptVersionId=368927596)

**Provenance des corrections.** La v3 GPU conservait une assertion de gel en échec avant la cellule qui gelait effectivement les poids. La copie Git initialise le modèle puis exécute le gel et son contrôle dans l’ordre. Elle vérifie aussi les versions Python, timm et Lightning et aligne l’indicateur GPU du notebook sur le Tesla T4 enregistré. La v1 CPU conservait le résultat `PASS` et le rapport, mais omettait les instructions qui chargeaient les poids et calculaient les tenseurs comparés. La copie Git rétablit ces instructions dans une cellule identifiée, sans lui attribuer de sortie Kaggle. Les rapports, les tableaux de référence et les sorties scientifiques des cellules réussies sont conservés.

**Vérification de la copie Git.** Sous Windows (Python 3.13.3, versions CPU de Torch/Torchvision et mêmes versions Anomalib/timm/Lightning), la cellule rétablie a rechargé le checkpoint à l’empreinte vérifiée et évalué l’image de validation avec le pipeline du dépôt. Le score obtenu vaut `30.64944839477539` et l’écart maximal de carte face au NPZ GPU vaut `0.0005321502685546875`, dans les tolérances ci-dessus. Le rapport CPU archivé provient de la session Kaggle indépendante.

Cette expérience vérifie une chaîne technique sur huit normales et une image de validation. Le score est brut. La calibration d’un seuil et les mesures de détection et de localisation sur des défauts réels restent à réaliser.
